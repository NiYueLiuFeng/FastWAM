# FastWAM 自定义 LeRobot 数据训练与推理教程

本教程面向**自带 LeRobot 格式数据**（LeRobot 2.1 或 3.0）的用户，介绍如何在自己的数据上训练 FastWAM，并用训练得到的 checkpoint 做推理。

整体流程：

```text
数据自检 → 编写 data config → 编写 task config → 生成 ActionDiT backbone
        →（可选）预计算文本嵌入 → 训练（自动生成 dataset_stats.json）
        → 推理（仿真 benchmark 或自定义推理循环）
```

---

## 一键启动（推荐）

如果数据已经是 LeRobot 2.0 / 2.1 / 3.0 格式，可以直接用
`scripts/train_custom.sh`，无需手写配置：

```bash
# 传数据集路径：自动读取 meta/info.json，生成 data/task 配置后启动训练
bash scripts/train_custom.sh --dataset ./data/my_dataset_v30 --gpus 4

# 多个数据集（fps、相机集合、action/state 维度必须一致）
bash scripts/train_custom.sh \
  --dataset ./data/ds_a --dataset ./data/ds_b --gpus 4

# 已有配置：task 名 / task 文件 / data 文件
bash scripts/train_custom.sh --task my_task --gpus 4
bash scripts/train_custom.sh --task-file /path/to/my_task.yaml --gpus 4
bash scripts/train_custom.sh --data-config /path/to/my_data.yaml --gpus 4
```

> 多数据集的完整流程（冲突校验、统一列名/fps、混合配置）见**第 10 节**。

脚本会自动完成：

1. 从 `meta/info.json` 推导 reader 版本、相机名、`action`/`observation.state` 维度；
2. 生成 `configs/data/autogen_<name>.yaml` 与 `configs/task/autogen_<name>.yaml`
   （带 `AUTOGENERATED` 头；同名手写文件默认拒绝覆盖，可用 `--force`）；
3. 校验配置（帧窗口整除约束、`video_size` 16 倍数、维度一致性等）；
4. 检查 ActionDiT backbone 与文本嵌入缓存。**缺失时只打印需要执行的命令并退出，
   不会自动运行重任务**；
5. 调用现有 `scripts/train_zero1.sh <gpus> task=autogen_<name> ...` 启动训练。

正式训练时输出同时写终端和日志文件（`--dry-run` 不写）：

```text
<repo>/log/<yyyy-mm-dd>_<model>_<task>.log
# 例：log/2026-10-23_fastwam_autogen_my_ds.log
```

- `<model>` 依次取 `--model`、`--extra "model=..."`、task 配置里的 `override /model:`；
- 同一天、同模型、同任务再次运行会**追加**到同一文件，每次用 `=====` 分隔并记录
  启动时间和完整命令；
- 需要换目录用 `--log-dir PATH`（或环境变量 `LOG_DIR`），不需要日志用 `--no-log`；
- 日志文件已被 `.gitignore` 的 `*.log` 忽略，不会误提交。

训练产物（权重、`dataset_stats.json`）仍在 `runs/{task}/{run_id}/`，日志目录与之独立。

常用选项：

```bash
# 覆盖训练超参
bash scripts/train_custom.sh --dataset ./data/my_ds --gpus 8 \
  --batch-size 16 --epochs 10 --lr 1e-4

# 数据集策略（相机选择 / 拼接口径）
bash scripts/train_custom.sh --dataset ./data/my_ds --gpus 8 \
  --camera cam_high --camera cam_left_wrist --resize 224 224 \
  --concat horizontal --video-size 224 448

# 不预计算文本嵌入，训练时在线编码
bash scripts/train_custom.sh --dataset ./data/my_ds --gpus 8 --online-text-encode

# 只生成配置、检查前置条件并打印最终命令，不真正训练
bash scripts/train_custom.sh --dataset ./data/my_ds --gpus 8 --dry-run

# 追加/覆盖任意 Hydra 参数
bash scripts/train_custom.sh --dataset ./data/my_ds --gpus 8 \
  --extra "model.compile_training_denoise=true"
```

> 生成的 data 配置默认使用：单相机不拼接、多相机水平拼接、每相机 224×224、
> `delta_action_dim_mask` 全 `false`、`min/max` 归一化。动作维是否为 delta
> 无法从数据推断，需要时用 `--delta-mask` 显式指定。
>
> `--help` 可查看全部参数。下面的 1–9 节是等价的手动流程，便于精细控制。

## 1. 环境准备

### 1.1 安装

参见 [README](../README.md#environment-setup)：

```bash
conda create -n fastwam python=3.10 -y
conda activate fastwam
pip install -U pip
pip install torch==2.7.1+cu128 torchvision==0.22.1+cu128 --extra-index-url https://download.pytorch.org/whl/cu128
pip install -e .
```

### 1.2 模型准备（训练前必须，只需做一次）

设置 Wan 模型目录（可选，默认 `./checkpoints`，首次运行会自动下载 Wan2.2 权重）：

```bash
mkdir -p checkpoints
export DIFFSYNTH_MODEL_BASE_PATH="$(pwd)/checkpoints"
```

预生成 ActionDiT backbone：

```bash
python scripts/preprocess_action_dit_backbone.py \
  --model-config configs/model/fastwam.yaml \
  --output checkpoints/ActionDiT_linear_interp_Wan22_alphascale_1024hdim.pt \
  --device cuda \
  --dtype bfloat16
```

> 说明：backbone 由 Wan22 DiT 插值而来，其中与 `action_dim` 相关的输入/输出层会被跳过，
> 因此**不同动作维度的数据可以复用同一个 backbone 文件**，无需按 action_dim 重新生成。
> 推理时不再需要该文件（checkpoint 中已包含全部权重）。

## 2. 数据要求

FastWAM 通过 `shape_meta` 中的 key 映射到 LeRobot 列名：

| shape_meta 条目 | 映射到的 LeRobot 列 |
| --- | --- |
| `images: key: image` | `observation.images.image` |
| `images: key: wrist_image` | `observation.images.wrist_image` |
| `state: key: default` | `observation.state` |
| `action: key: default` | `action` |

即数据需符合 LeRobot 标准命名（`observation.images.<相机名>`、`observation.state`、`action`），
且每帧任务文本通过 `meta/tasks.jsonl` / parquet 中的 `task` 列提供。

若动作/状态列不是标准命名（例如动作列叫 `actions`），无需改动数据集，
生成配置时显式指定列名即可：

```bash
bash scripts/train_custom.sh --dataset ./data/my_dataset_v30 \
  --action-feature actions --state-feature observation.state --gpus 4
# 或直接调用生成器：
python scripts/prepare_custom_training.py generate --dataset ./data/my_dataset_v30 \
  --action-feature actions --print-name
```

生成的 data config 会在对应条目下写入 `lerobot_key: actions`，
读取器（`base_lerobot_dataset.py`）优先使用该字段，未写入时仍按上表推导。
相机列目前只支持 `observation.images.<相机名>`。

### 2.1 目录结构

**LeRobot 2.1**（`_target_: fastwam.datasets.lerobot.robot_video_dataset.RobotVideoDataset`）：

```text
data/my_dataset/
├── meta/
│   ├── info.json          # 含 fps、total_episodes、视频/特征列定义
│   ├── episodes.jsonl
│   └── tasks.jsonl        # 任务指令文本（训练文本编码会扫描此文件）
├── data/
│   └── chunk-000/
│       └── episode_000000.parquet
└── videos/
    └── chunk-000/
        └── observation.images.image/
            └── episode_000000.mp4
```

**LeRobot 3.0**（`_target_: fastwam.datasets.lerobot3.robot_video_dataset.RobotVideoDataset`，
分块 parquet + 视频，规模扩展性更好）：

```text
data/my_dataset_v30/
├── meta/  ...
├── data/chunk-000/...
└── videos/chunk-000/...
```

### 2.2 硬性约束（不满足会直接报错或断言失败）

1. **多个数据目录的 fps 必须一致**（`base_lerobot_dataset.py` 中有显式 assert）。
   fps 不同时用 `scripts/adapt_dataset_for_training.py --fps` 统一，详见第 10 节。
2. **时间窗口约束**：默认 `num_frames=33`、`action_video_freq_ratio=4`，
   即每个训练样本取 33 帧观测 → 32 步动作、9 帧视频（每 4 帧取 1 帧）。
   若修改，必须满足：
   - `(num_frames - 1) % action_video_freq_ratio == 0`
   - `((num_frames - 1) // action_video_freq_ratio) % 4 == 0`
3. **动作/状态维度**：parquet 中 `action` / `observation.state` 的最后一维必须与
   `shape_meta` 中 `raw_shape` 完全一致（processor 里有 assert）。
4. **episode 长度**：短于 `num_frames` 的 episode 会被 padding（`*_is_pad`），
   delta 动作维度在 pad 处会被置零。建议尽量保证每条 episode ≥ 33 帧。
5. **分辨率**：原始图像分辨率任意（加载时会 resize），但最终 `video_size`
   （多相机拼接后）的 H、W 必须是 **16 的倍数**（VAE 要求）。
6. 数据中每帧需带有 `task` 指令文本（LeRobot 标准字段）。
7. **`meta/info.json` 的 `features` 必须与 `data/*.parquet` 的实际列名一致**。
   训练读取器直接按 `features` 选列（`columns=list(features)`），列名对不上会在
   构建数据集时报 `ArrowInvalid: No match for FieldRef.Name(frame_index)`。
   常见的半成品数据是把 `frame_index` 写成了 `frame_idx`，用
   `scripts/fix_dataset_columns.py --dataset <dir> --write` 原地改列名即可
   （`train_custom.sh` 的前置检查也会提前拦下）。

### 2.3 语义约定（强烈建议）

- `action` 建议使用 **delta EEF pose + 绝对 gripper** 之类的组合，并在
  `delta_action_dim_mask` 中如实标注哪些维是 delta（用于 padding 置零）。
- 归一化统计（min/max 或 z-score）由训练首次运行自动计算，无需手工准备。

## 3. 第一步：编写 data config

以 `configs/data/libero_2cam_lerobot_v30.yaml` 为模板，复制为
`configs/data/mydata_2cam.yaml`（2.1 数据把 `_target_` 换回
`fastwam.datasets.lerobot.robot_video_dataset.RobotVideoDataset` 并删掉 `video_backend`）：

```yaml
train:
  _target_: fastwam.datasets.lerobot3.robot_video_dataset.RobotVideoDataset  # 3.0；2.1 用 fastwam.datasets.lerobot...
  dataset_dirs:
    - ./data/my_dataset_v30            # ← 改成你的数据目录，可多个
  shape_meta:
    images:
      - key: image                     # ← 对应 observation.images.image
        raw_shape: [3, 512, 512]       # 原始分辨率（state/action 用于强校验；图像仅作记录）
        shape: [3, 224, 224]           # 每个相机 resize 后的尺寸，需与下方 train_transforms 一致
      - key: wrist_image               # ← 第二个相机
        raw_shape: [3, 512, 512]
        shape: [3, 224, 224]
    action:
      - key: default
        raw_shape: 7                   # ← 你的 action 维度
        shape: 7
    state:
      - key: default
        raw_shape: 8                   # ← 你的 observation.state 维度
        shape: 8
  num_frames: 33                       # 33 帧 → 32 步动作、9 帧视频
  global_sample_stride: 1
  action_video_freq_ratio: 4
  video_size: [224, 448]               # 多相机拼接后的最终输入尺寸 [H, W]，须为 16 的倍数
  camera_key: null
  val_set_proportion: 0.0              # 留出验证集比例；0.0 表示全部用于训练
  is_training_set: true
  skip_padding_as_possible: false
  concat_multi_camera: "horizontal"    # 多相机拼接方式：horizontal / vertical / robotwin
  processor:
    _target_: fastwam.datasets.lerobot.processors.fastwam_processor.FastWAMProcessor
    shape_meta: ${data.train.shape_meta}
    num_obs_steps: ${data.train.num_frames}
    num_output_cameras: 2              # ← 相机数量
    action_output_dim: 7               # ← 与 shape_meta.action.shape 一致
    proprio_output_dim: 8              # ← 与 shape_meta.state.shape 一致
    delta_action_dim_mask:
      default: [true, true, true, true, true, true, false]  # ← 标注哪些动作维是 delta
    action_state_transforms: null      # 若需对 action/state 做变换（如欧拉角→轴角），在此配置
    use_stepwise_action_norm: false
    norm_default_mode: min/max         # LIBERO 用 min/max；RoboTwin 用 z-score，二选一
    norm_exception_mode: null
    action_state_merger:
      _target_: fastwam.datasets.lerobot.transforms.action_state_merger.ConcatLeftAlign
    train_transforms:
      - _target_: fastwam.datasets.lerobot.transforms.image.ToTensor
      - _target_: torchvision.transforms.Resize
        size: [224, 224]               # ← 每个相机 resize 到 [H, W]，与 shape_meta.images.shape 一致
    val_transforms:
      - _target_: fastwam.datasets.lerobot.transforms.image.ToTensor
      - _target_: torchvision.transforms.Resize
        size: [224, 224]
  text_embedding_cache_dir: ./data/text_embeds_cache/mydata   # ← 文本嵌入缓存目录
  use_text_embed_cache: true
  context_len: 128
  video_backend: pyav                  # 3.0 数据建议保留；2.1 数据删掉此行
```

### 需要重点确认的字段

| 字段 | 说明 |
| --- | --- |
| `dataset_dirs` | 你的数据根目录（含 `meta/` 的那层），可传多个，fps 必须一致 |
| `shape_meta.images[*].key` | 必须与数据中的相机列名一致（`observation.images.<key>`） |
| `shape_meta.action/state` 的 `raw_shape`/`shape` | 与数据实际维度一致（不使用 `action_state_transforms` 时两者相等） |
| `video_size` | 多相机拼接后的最终尺寸。`horizontal` 拼接 2 个 224×224 相机 → `[224, 448]`；H、W 均须为 16 的倍数 |
| `num_output_cameras` / `action_output_dim` / `proprio_output_dim` | 与相机数、动作/状态维度一致（`action_output_dim` 会经 `${...}` 自动注入模型配置） |
| `norm_default_mode` | `min/max`（LIBERO 风格）或 `z-score`（RoboTwin 风格） |
| `val_set_proportion` | 需要验证集时设为如 `0.01`，并仿照 `configs/data/robotwin.yaml` 增加一个 `val:` 节点（`is_training_set: false` 且必须提供 `pretrained_norm_stats`） |

> 相机数量说明：LIBERO 配置为 2 相机水平拼接；RoboTwin 用 3 相机专用 `concat_multi_camera: "robotwin"`
> 布局（生成 384×320）。单相机数据将 `concat_multi_camera` 设为 `null`、`video_size` 设为该相机尺寸即可。

## 4. 第二步：编写 task config

复制 `configs/task/libero_uncond_2cam224_1e-4.yaml` 为
`configs/task/mydata_uncond_2cam224_1e-4.yaml`：

```yaml
# @package _global_

defaults:
  - override /data: mydata_2cam        # ← 你的 data config 名（不含 .yaml）
  - override /model: fastwam           # fastwam / fastwam_idm / fastwam_joint / fastwam_optional_idm
  - _self_

# dataloading
batch_size: 16
num_workers: 8

model:
  mot_checkpoint_mixed_attn: false

# scheduler
lr_scheduler_type: "cosine"
learning_rate: 1e-4
num_epochs: 10                         # ← 按数据规模调整
max_steps: null
log_every: 10
save_every: 2000
eval_every: 200

# training
gradient_accumulation_steps: 1
weight_decay: 1e-2
resume: null
```

`model.action_dit_config.action_dim` 和 `video_dit_config.action_dim` 会通过
`${data.train.processor.action_output_dim}` 自动从 data config 注入，无需手改。

## 5. 第三步（可选）：预计算文本嵌入

训练时有两种文本编码方式：

**方式 A：预计算缓存（默认，吞吐最高）**

`precompute_text_embeds.py` 会扫描所有 `dataset_dirs` 的 `meta/tasks.jsonl`，
对去重后的指令批量编码并写入 `text_embedding_cache_dir`：

```bash
python scripts/precompute_text_embeds.py task=mydata_uncond_2cam224_1e-4

# 多卡：
torchrun --standalone --nproc_per_node=8 scripts/precompute_text_embeds.py task=mydata_uncond_2cam224_1e-4
```

**方式 B：训练时在线编码（免预处理，约慢 10%）**

修改两处：

```bash
bash scripts/train_zero1.sh 8 task=mydata_uncond_2cam224_1e-4 \
  data.train.use_text_embed_cache=false \
  model.load_text_encoder=true
```

## 6. 第四步：训练

**首次训练**：不要设置 `pretrained_norm_stats`（保持缺省 `null`）。
训练初始化时会在 rank 0 上遍历全数据集自动计算归一化统计，并保存到：

```text
runs/{task_name}/{run_id}/dataset_stats.json
```

```bash
bash scripts/train_zero1.sh 8 task=mydata_uncond_2cam224_1e-4

# 可选：加速训练（约 +10%）
bash scripts/train_zero1.sh 8 task=mydata_uncond_2cam224_1e-4 \
  model.compile_training_denoise=true
```

多机训练通过环境变量控制：

```bash
NNODES=2 NODE_RANK=0 MASTER_ADDR=<主节点IP> MASTER_PORT=29500 \
  bash scripts/train_zero1.sh 8 task=mydata_uncond_2cam224_1e-4
```

**后续训练**：把 `pretrained_norm_stats` 指向首次运行生成的 `dataset_stats.json`
（命令行覆盖即可，不必改文件）：

```bash
bash scripts/train_zero1.sh 8 task=mydata_uncond_2cam224_1e-4 \
  data.train.pretrained_norm_stats=./runs/mydata_uncond_2cam224_1e-4/<run_id>/dataset_stats.json
```

训练产物位于 `runs/{task_name}/{run_id}/`：

```text
runs/mydata_uncond_2cam224_1e-4/{run_id}/
├── dataset_stats.json               # 归一化统计（推理必需）
└── checkpoints/
    ├── weights/{step}.pt            # 模型权重（推理用这个）
    └── state/                       # 完整训练状态（断点续训用）
```

> 提示：训练前可先用 `python scripts/dryrun_fastwam.py task=... ckpt=...`
> 验证模型构建与推理链路（合成输入，不需要环境）。

## 7. 推理

### 7.1 情形一：数据来自 LIBERO / RoboTwin 仿真

若你的 LeRobot 数据与官方 LIBERO / RoboTwin 仿真环境对应，直接用仓库自带的评测入口，
把 `task`、`ckpt`、`dataset_stats_path` 指向你自己的训练产物即可：

```bash
# LIBERO（需先安装官方 LIBERO 环境和 mujoco==3.3.2）
python experiments/libero/run_libero_manager.py \
  task=mydata_uncond_2cam224_1e-4 \
  ckpt=./runs/mydata_uncond_2cam224_1e-4/<run_id>/checkpoints/weights/<step>.pt \
  EVALUATION.dataset_stats_path=./runs/mydata_uncond_2cam224_1e-4/<run_id>/dataset_stats.json \
  EVALUATION.sigma_shift=1.0 \
  MULTIRUN.num_gpus=8

# RoboTwin（需按官方 RoboTwin 仓库安装环境、下载资产并建好 policy 软链）
python experiments/robotwin/run_robotwin_manager.py \
  task=mydata_uncond_3cam_384_1e-4 \
  ckpt=<ckpt_path> \
  EVALUATION.dataset_stats_path=<dataset_stats.json> \
  EVALUATION.sigma_shift=1.0
```

### 7.2 情形二：自定义机器人 / 环境（最小推理循环）

对真实机器人或自建环境，参考 `experiments/libero/eval_libero_single.py` 中的
`_predict_action_chunk`，核心步骤是：

1. `instantiate(cfg.model)` 构建模型并 `load_checkpoint`（推理时
   `model.load_text_encoder=true`、`model.skip_dit_load_from_pretrain=true`、
   `model.action_dit_pretrained_path=null`）；
2. 用训练时的 data config 构建 `FastWAMProcessor`，并载入 `dataset_stats.json`；
3. 每个相机按 `shape_meta.images[*].shape` resize（保持长宽比 + 中心裁剪），
   按 `concat_multi_camera` 拼接，尺寸应等于 `video_size`，再归一化到 `[-1, 1]`；
4. `observation.state` 用 processor 归一化后作为 `proprio` 输入；
5. 调 `model.infer_action(...)` 得到归一化动作块，反归一化后按
   `replan_steps` 执行前若干步，然后重新观测、循环。

仓库提供了可直接改写的最小模板 [`examples/infer_custom.py`](../examples/infer_custom.py)，
其中与机器人/环境交互的三个函数（`get_observation` / `step_env` / `done`）留作占位，
替换成你自己的 API 即可。运行方式（`+` 前缀用于追加 train.yaml 中不存在的键）：

```bash
python examples/infer_custom.py \
  task=mydata_uncond_2cam224_1e-4 \
  +ckpt=./runs/mydata_uncond_2cam224_1e-4/<run_id>/checkpoints/weights/<step>.pt \
  +dataset_stats_path=./runs/mydata_uncond_2cam224_1e-4/<run_id>/dataset_stats.json \
  model.load_text_encoder=true \
  model.skip_dit_load_from_pretrain=true \
  model.action_dit_pretrained_path=null \
  +CUSTOM.task_description="put the bowl on the plate" \
  +CUSTOM.replan_steps=10 \
  +CUSTOM.num_inference_steps=20 \
  +CUSTOM.sigma_shift=1.0
```

> 注意事项：
>
> - **指令模板必须与训练一致**（`DEFAULT_PROMPT`），模型对 prompt 措辞敏感。
> - **相机顺序必须与 `shape_meta.images` 顺序一致**（第 1 个通常是主视角）。
> - `proprio` 是**当前帧**的 `observation.state`（与训练时对齐）。
> - `sigma_shift`：新训练的模型默认 `1.0`（训练/推理一致即可）；官方原始 checkpoint 用 `5.0`。
> - 训练了 `fastwam_idm` / `fastwam_optional_idm` 变体时，`infer_action` 额外支持
>   `action_infer_mode`（`idm` / `first_frame`）；`fastwam`（uncond）无需该参数。
> - 动作语义（如 gripper 的开合约定、坐标系）由你的数据决定，反归一化后请按
>   你自己的采集约定下发，必要时参考 `eval_libero_single.py` 中的 gripper 翻转/二值化处理。

## 8. 常见问题排查

| 现象 | 原因与解决 |
| --- | --- |
| `数据集中找不到 action 特征 'action'` | 数据集把动作列命名为 `actions` 等非标准名，加 `--action-feature actions`（状态列同理用 `--state-feature`） |
| `All dataset_dirs must have the same fps` | 多个数据目录 fps 不一致：先用 `scripts/adapt_dataset_for_training.py --fps` 统一（第 10.3 节），或去掉不一致的目录 |
| `Action 'default' shape ... mismatch with meta` | `shape_meta.action.raw_shape` 与数据实际维度不符，改成一致 |
| `Missing text embedding cache: ...` | 未预计算文本嵌入：运行 `scripts/precompute_text_embeds.py`，或改用在线编码（第 5 节方式 B） |
| `input_image must be resized before infer, expected multiples of 16` | 拼接后的图像尺寸不是 16 的倍数，检查 `video_size` 与各相机 `shape` |
| `num_frames-1 must be divisible by action_video_freq_ratio` | 自定义 `num_frames` / `action_video_freq_ratio` 不满足第 2.2 节的整除约束 |
| `Concatenated image ... != video_size` | 推理时的相机 resize/拼接方式与训练不一致，对照第 7.2 节步骤 3 |
| 首次训练很慢才开始 | 正在遍历数据集计算归一化统计（只发生一次），完成后写入 `dataset_stats.json` |
| 启动后报 `ArrowInvalid: No match for FieldRef.Name(frame_index)` / `DatasetGenerationError` / `Error in call to target '...RobotVideoDataset'`，`full_key: data.train` | `meta/info.json` 声明了 `frame_index`，但 `data/*.parquet` 里这列叫 `frame_idx`（转换脚本版本不同留下的半成品）。先 `python scripts/fix_dataset_columns.py --dataset <dir>` 看计划，确认后加 `--write` 原地改列名；改完重新跑训练即可。`check_data_merge_train.py` 与 `train_custom.sh` 的前置检查都会报这个 |
| 启动几十秒后报 `ncclUnhandledCudaError ... Cuda failure 2 'out of memory'`，落在 `data.train`（`Calculating dataset stats for normalization` 附近） | 卡上已有别的进程占显存，模型/梯度装不下。先 `nvidia-smi` 看空闲显存，换到空卡或等占用任务结束；本仓库的 `train_custom.sh` 会在启动前检查每张卡的空闲显存并直接报错（阈值 `MIN_FREE_GPU_MEM_GB`，默认 24，`--skip-prereq-check` 可跳过检查） |
| 评测报找不到 `dataset_stats.json` | 显式传 `EVALUATION.dataset_stats_path`，或把该文件放在 checkpoint 同级/上级目录 |

## 10. 多数据集混合训练（校验 → 适配 → 训练）

本节对应容器 readme 里的「训练脚本-多数据集」。

FastWAM 支持把多个 LeRobot 数据集放进同一个训练任务：读取器用
`MultiLeRobotDataset` 把各数据集**按帧拼接**（帧数多的数据集被采样到的比例更高），
所有数据集共用一套归一化统计和一个采样器。因此数据集之间必须满足一组硬性约束，
不满足时用本节介绍的两个脚本先做校验和适配。

```text
校验（check_data_merge_train.py）
  → 有冲突就适配（adapt_dataset_for_training.py）
  → 重新校验
  → 生成多数据集配置（prepare_custom_training.py generate）
  → 预计算文本嵌入（precompute_text_embeds.py）
  → dry-run → 正式训练
```

### 10.1 混合训练的前提

| 项目 | 要求 | 不一致时的表现 |
| --- | --- | --- |
| `codebase_version` | 一致（2.0 / 2.1 / 3.0 选一种） | 生成配置时报错 |
| `fps` | 一致 | `[FAIL] fps 不一致` |
| action 列 | 列名、子特征（`action.<key>`）、维度一致 | `[FAIL] action 列名/维度不一致` |
| state 列 | 列名、子特征、维度一致 | `[FAIL] state 列名/维度不一致` |
| 相机集合 | 一致；或显式 `--camera` / `--intersect-cameras` | `[FAIL] 相机集合不一致` |
| 采样窗口 | `(num_frames-1)*stride+1` ≤ 每个数据集最短的“最长 episode” | 运行期取帧越界 |

可以不同的部分：

- **分辨率**：加载时每个相机各自 resize 到 `--resize`（默认 224×224）后再拼接；
- **episode 数、任务文本数**：任务文本会合并去重；验证集（`val_proportion`）按数据集各自切分；
- **数据量**：合并后按帧数加权采样，数据量大的数据集占比更高。

> 归一化统计在合并后的数据集上统一计算一次（写入 `dataset_stats.json`），
> 不会为每个数据集单独保存。

### 10.2 第一步：前置校验

`scripts/check_data_merge_train.py` 只读元数据、不修改任何文件，判断规则与
`prepare_custom_training.py generate` 内部的 `merge_probes` 一致，并额外核对
`meta/info.json` 与实际 parquet 的列是否对得上（防止“只改了 meta 没改数据”）。

```bash
python scripts/check_data_merge_train.py \
    --dataset /workspace/data/ds_a \
    --dataset /workspace/data/ds_b \
    --action-feature actions
```

退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 可以混合训练 |
| 1 | 存在冲突，逐条列出原因与修复命令 |
| 2 | 参数或数据集路径错误 |

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--action-feature NAME` | action 列名（默认 `action`），所有数据集共用同一个值 |
| `--state-feature NAME` | state 列名（默认 `observation.state`） |
| `--camera KEY` | 只用这些相机（去掉 `observation.images.` 前缀，可重复） |
| `--intersect-cameras` | 取所有数据集的公共相机（默认要求相机集合完全一致） |
| `--num-frames` / `--global-sample-stride` / `--action-video-freq-ratio` | 采样窗口检查 |

输出示例：

```text
== 数据集 2/2: /workspace/data/ds_b
   version : 3.0  (fastwam.datasets.lerobot3.robot_video_dataset.RobotVideoDataset)
   fps     : 30
   action  : actions[13]
   state   : observation.state[13]

== 交叉检查
   [FAIL] fps 不一致: ds_a=15, ds_b=30
          -> python scripts/adapt_dataset_for_training.py \
             --src /workspace/data/ds_b --dst /workspace/data/ds_b_15 --fps 15
结果: 不可混合训练（1 项 FAIL，0 项 WARN）
```

> 脚本对所有 `--dataset` 使用同一个 `--action-feature` / `--state-feature`。
> 如果两个数据集的列名本就不同，按提示统一命名后，后续所有命令都要用新名字。

### 10.3 第二步：适配数据（仅在需要时）

`scripts/adapt_dataset_for_training.py` 把源数据集**完整复制到新目录**并同步改写，
不修改原数据。支持两种操作，可单独或组合：

- `--rename OLD=NEW`：重命名特征列（例如 `actions` → `action`，可重复）；
- `--fps N`：按比例抽帧（**只支持降低**），把 fps 统一到较低值。

```bash
# 只统一 fps：ds_b 30fps -> 15fps
python scripts/adapt_dataset_for_training.py \
    --src /workspace/data/ds_b \
    --dst /workspace/data/ds_b_15 \
    --fps 15 \
    --dry-run          # 先打印计划；确认后去掉 --dry-run

# 只统一列名
python scripts/adapt_dataset_for_training.py \
    --src /workspace/data/ds_b --dst /workspace/data/ds_b_renamed \
    --rename actions=action

# 两者同时
python scripts/adapt_dataset_for_training.py \
    --src /workspace/data/ds_b --dst /workspace/data/ds_b_15_action \
    --fps 15 --rename actions=action
```

同步改写的内容：

| 位置 | 改动 |
| --- | --- |
| `meta/info.json` | `features` 键名；`fps`、`total_frames`（`splits` 的 episode 区间不变） |
| `meta/stats.json` | 键名；按抽帧后的数据重算 `count/min/max/mean/std` |
| `meta/episodes/*.parquet` | `stats/<feature>/*`、`videos/<feature>/*` 列名；`length`、`dataset_from/to_index` 及可重算的统计量 |
| `data/*.parquet` | 列名；抽帧后的行，重算 `frame_index` / `index` / `is_first` / `is_last` |
| `videos/` | 默认相对路径符号链接（不占额外空间）；改视频特征名时同步改目录名 |

实现要点与限制：

- **视频不重新编码**。抽帧保留原始 `timestamp` 列，读取器按时间戳取视频帧；
  被保留帧的时间戳恰好等于新 fps 下的时间戳，因此画面与动作仍严格对齐。
- `--copy-videos` 改为真实复制（跨文件系统、或需要独立分发数据集时用），
  空间占用与原数据相同。
- 输出目录必须不存在；`--force` 只允许删除**本工具生成过**的目录（有
  `.adapt_dataset_for_training.json` 标记文件校验）。
- 只支持降低 fps；提高 fps 需要重编码视频（插值），本工具不做。
- 目标是同一个挂载目录下的相对路径符号链接，所以 `--dst` 应与 `--src`
  位于同一挂载树内（例如都放在 `/workspace/data` 下）。
- 支持 LeRobot 2.0 / 2.1 / 3.0；3.0 要求同一文件内的 episode 连续、
  `episode_index` 跨文件严格递增（LeRobot 官方导出默认满足）。

### 10.4 第三步：重新校验

```bash
python scripts/check_data_merge_train.py \
    --dataset /workspace/data/ds_a \
    --dataset /workspace/data/ds_b_15 \
    --action-feature actions
```

看到 `结果: 可以混合训练` 后再继续。

### 10.5 第四步：生成多数据集配置

```bash
python scripts/prepare_custom_training.py generate \
    --dataset /workspace/data/ds_a \
    --dataset /workspace/data/ds_b_15 \
    --name mixed_ab \
    --action-feature actions \
    --camera front --camera wrist \
    --num-frames 33 \
    --resize 224 224 \
    --concat horizontal \
    --print-name
# -> autogen_mixed_ab
```

说明：

- `--dataset` 可重复；`--name` 决定配置文件名 `autogen_<name>.yaml`，
  不写时按数据集目录名拼接，建议显式指定；
- 数据集级的策略（相机、拼接、resize、帧数、归一化方式、验证集比例）
  对所有数据集统一生效；
- 生成后配置里 `train.dataset_dirs` 会列出全部数据集。

### 10.6 第五步：文本嵌入与训练

```bash
# 文本嵌入会遍历配置中所有数据集，合并去重任务文本
python scripts/precompute_text_embeds.py task=autogen_mixed_ab

# dry-run：检查 backbone、文本缓存并打印最终命令
bash scripts/train_custom.sh \
    --dataset /workspace/data/ds_a --dataset /workspace/data/ds_b_15 \
    --name mixed_ab --action-feature actions \
    --camera front --camera wrist --gpus 4 \
    --backbone /workspace/checkpoints/ActionDiT_linear_interp_Wan22_alphascale_1024hdim.pt \
    --dry-run

# 正式训练：与 dry-run 参数完全一致，去掉 --dry-run
```

> `train_custom.sh` 每次都会按 `--dataset / --camera / --action-feature` 重新生成
> 配置，所以 dry-run 与正式训练的参数必须一致；参数变了会得到另一份配置
> （也可能用到另一份文本缓存）。

也可以跳过 `prepare_custom_training.py`，直接用 `train_custom.sh --dataset ...`
（见“一键启动”），但建议先用第 10.2 节的校验脚本确认数据集之间没有冲突。

### 10.7 常见冲突与处理

| 现象 | 处理 |
| --- | --- |
| `[FAIL] fps 不一致` | `adapt_dataset_for_training.py --fps <较低值>` |
| `[FAIL] action 列名/维度不一致` | 仅列名不同：`--rename actions=action`；维度不同（13 vs 7）无法拼接，需重新导出数据 |
| `[FAIL] 相机集合不一致` | 加 `--intersect-cameras` 取交集，或 `--camera` 显式选择双方都有的相机 |
| `[FAIL] codebase_version 不一致` | 重新导出为同一版本（本工具不做版本迁移） |
| `[FAIL] 数据集 X 的最长 episode 只有 N 帧，小于采样窗口 M 帧` | 减小 `--num-frames` / `--global-sample-stride`，或去掉该数据集 |
| `--dst 已存在` | 换输出目录；确认是上次产物时加 `--force` |
| 抽帧后训练收敛变慢 | fps 减半后，同样的 `num_frames=33` 覆盖的时间跨度变成 2 倍；可按需调整 `num_frames` 或 `global_sample_stride` |
